Android 版的 iOS 原生 SwiftUI 移植。

## v1.22.0 — 已保存连接重做、报错会自己走、黑边加了现场诊断

- **已保存连接整块重写**（`SettingsView.connectionsCard / connectionRow`）：
  - 以前这一块只有「连接数 > 1」才出现，只剩一条连接时根本没法编辑/删除；
    打开路由器的开关又会把展开状态忘掉。现在它是一张独立的卡，始终可见，
    顶部是「N 个连接 · 点名称即可切换」+「新建」，空列表有引导文案。
  - 每一行：头像（当前那条是蓝色实心）+ 名称 + `user@host:port` + 「当前」绿标 + 「…」。
    点左半边即切换（当前那条不可点），「…」在行内展开 编辑 / 删除 两个胶囊。
  - 删除改成 `confirmationDialog` 二次确认，并说明会一并删掉钥匙串里的密码。
  - 修掉删除的一个真 bug：删的正好是当前会话时，SSH 还连着那台、列表里却没有了，
    界面会卡在「已连接」上 —— 现在会一并断开（`keepPassword: true`，不会误删新选中那条的密码）。
  - 「自动登录」从角落里的小开关变成一整行（图标 + 说明 + 开关）。
  - 正在连接的那一行显示转圈，不再只靠顶部胶囊。
- **错误提示会自己消失**：新增 `AppModel.presentError` / `clearError`，
  8 秒自动过期（连接失败给 12 秒），页面上也能点叉立刻收掉；`describe()` 不再拼
  `[domain code]` 和 `String(describing:)`，只留一句人话。统一成 `ErrorBanner`。
- **网络代理：拿到状态后自动跑一次访问检测**：进页面第一次采集成功后，静默跑一次
  `checkAccess(silent:)`（不弹全屏遮罩、失败不弹红字，15 秒内不重复）。
  检测脚本改成四个站点**并行**探、毫秒换算搬回 Swift，整条命令最多一个 `-m 4`，
  不再串行 20 秒把轮询堵住。卡片上补了「最近检测 hh:mm:ss」和「x/4 可达」。
- **控制面板单独成卡**（`ProxyView.panelCard`）：原来挤在「配置与控制面板」最底下，
  只有 12pt 字的「打开」小胶囊。现在有图标、地址（host:port · dashboard）、
  「可打开 / 未就绪」状态和一条 44pt 高的整行主按钮，未就绪时给出具体原因。
- **闪存数字终于对得上**（`FlashInfo` + `updateFlash`）：`/rom` 是只读 squashfs，
  `df` 的 Used 就是整块固件；`/overlay` 是另一块分区、各报各的总量。以前拿
  `/overlay` 的 1K-blocks 当 total，再加上 `/rom` 的用量，会算出
  「已用 30 MB、剩余 90 MB、共 100 MB」这种自相矛盾的组合，进度条（三段各自归一）
  也就和右上角百分比不一致。现在 total 直接用 系统 + 应用 + 可用 三者之和，
  三段共用同一个分母，条填到哪儿就等于百分比，三个数字永远加得起来。
- **黑边加了现场诊断**：新增 `ScreenInfo`（`UIScreen.bounds` 与 `nativeBounds` 之比），
  设置页「关于」里显示「屏幕 402 × 874 pt · 3×」和「运行模式 —— 原生全屏 / 兼容模式（放大 1.02×）」。
  一旦是兼容模式，下面直接写清楚要用 Xcode 16+ 重打包。

## v1.21.0 — 连接行改成行内操作、黑边定位到构建 SDK

- **「…」不再是系统 Menu**：`Menu` 飘在独立图层上，从它里面点「切换到这个连接」时
  连接弹窗立刻出现、菜单还在自己收，两个浮层叠在一起（就是截图里那团错乱），
  上一版加的 280ms 延时并不能保证。现在改成点「…」在那一行下面展开一条行内操作
  （切换 / 编辑 / 删除，胶囊按钮），全程没有浮层，也就不可能叠。展开哪一行由
  `expandedProfileID` 管理，收起路由器列表时一起清掉。
- **上下黑边 = 构建用的 SDK 太老**（iPhone 17 + iOS 27 实测）：用低于 iOS 26 的 SDK
  打包，系统不认识这块屏幕，会把 App 按兼容模式运行，内容缩在中间、上下各一条黑边
  （`UILaunchScreen` 之类都是齐的，问题不在这里）。对策：
  - workflow 的 `auto` 改成只排 `macos-26`（Xcode 26 / iOS 26 SDK），
    `macos-15` 只能手动选，且构建前会硬检查 `xcrun --sdk iphoneos --show-sdk-version`，
    低于 26 直接失败并说明原因；
  - `ios/build-unsigned-ipa.sh` 同样加了 SDK 检查；
  - `project.yml` 的 `xcodeVersion` 从 15.4 提到 26.0。

  `.toolbarBackground(.hidden, for: .navigationBar)`。栏全透明之后，滚动时内容会直接从
  标题文字下面穿过去——设置页的「设置」被路由器名字压住，概览页的「概览」被卡片标题压住，

  标题折叠成居中小字，不再叠加；二级页（采集与刷新 / 概览模块 / 连接设备）去掉该修饰，
  统一走系统默认。
- **连接设备改弹窗**：概览卡片里的「查看全部设备」由 `NavigationLink` 改为 `.sheet`，
  中等/全高两档（`presentationDetents`），列出名称 + IP + MAC，顶部带总台数与
  「仅 DHCP 租约」说明，右上角「完成」或下拉收起；概览的滚动位置和实时曲线不受影响。
  行标识改用 IP（`DeviceInfo.id` 每轮采集都会新建，用 id 会导致每 2 秒整体重建）。
- **连接可中止 + 可回退**（`SSHService.swift` / `AppModel.swift` 改动最大）：
  - 阻塞式 `connect()` 在跨网段时不按 `SO_SNDTIMEO` 返回，要等内核 SYN 重试约 75 秒，
    弹窗就一直「已等待 N 秒」。改为非阻塞 connect + `poll` 200ms 切片，8 秒超时并给出
    「请确认手机和路由器在同一网段」。
  - 新增 `SSHService.cancelAttempt()`：锁保护的取消标记 + `shutdown()` 正在握手的 fd，
    卡在 `connect()` 或 `libssh2_session_handshake` 里也能立刻退出（取消标记在派发前清，
    避免「点停止比队列排到还早」把标记抹掉；失败出口统一先摘 pendingFD 再 close，
    防止 fd 号被复用后误伤别的 socket）。
  - 弹窗 `connecting` 状态新增红色「停止连接」，次要操作保留「在后台继续」。
  - `connect(profile:password:)` 不再一上来 `disconnect()`：新会话握手成功才顶替旧会话，
    失败/超时/取消用 `attemptFallback`（上一台的 profileID、密码、是否已连接）原样回滚。
    `attemptToken` 让取消后的旧任务收尾失效；`attemptTarget` 让弹窗标题和「重试」
    认准这次尝试的目标（回滚后 `currentProfile` 已经变回上一台了）。
  - `lastConnectFailed` 明确区分「失败」与「取消」，弹窗据此显示失败还是成功
    （回滚后 `connected` 为真，只看它会把失败演成成功）。
  - `reconnect()` / 轮询的状态刷新在 `connecting` 期间让路，避免和新建连接抢会话。
  - 换会话时清空采样基线（`resetSamplingBaselines`）与上一台的数据，第一轮不会拿新旧做差。

## v1.18.0 — 代理页流量真正动起来、编辑连接不再变新建、闪存卡重画

- **实时流量终于会变**：`/traffic` 是**流式**接口——内核每秒吐一行
  `{"up":…,"down":…}` 并且不断开连接。旧命令用 `-m 3` 直接抓，一次会抓到两三行首尾相接，
  拼起来就是 `{"up":1}{"up":2}`，JSON 解析必然失败，数字永远停在 0（而 `/connections`
  是一次性返回的，所以连接数、内核状态一直是好的）。现在命令行尾加 `head -n 1`，
  只留第一行就关管道，配合 `-N` 拿到即输出；同时解析器改成按大括号配对切分、取**最后**
  一个对象，两种口径都吃得下。顺带把这一段的耗时从 3 秒压到 1 秒左右，
  轮询也改成「跑完一轮再按设置间隔补齐」，刷新节奏和用户设的秒数一致。
  万一固件上 `/traffic` 完全不可用，用 `/connections` 的累计值做差补一个速度，不会再一直显示 0。
- **第一次点「编辑」不会再打开新建**：原来用「布尔 + 单独保存要编辑的 profile」两个状态
  驱动 `.sheet(isPresented:)`，弹窗内容可能拿到还没写入的旧值（nil）。改成 `.sheet(item:)`
  由数据本身决定弹窗（`ConnectionEditorRoute`），表单字段也随 `.id` 重新初始化，
  填的就是这台路由器现在保存的信息。
- **闪存卡重新设计**：
  - 顶部：已用容量（圆体大数字）+「共 X · 剩余 Y」，右侧占用率按档位变色（≥90% 橙、≥97% 红）。
  - 进度条：系统占用（中性灰）+ 应用程序（蓝）拼成已用部分，两段之间留 2pt 缝看清楚边界，
    剩下的是轨道本身也就是可用空间；不再有「可用」那段盖在灰底上糊成一片的问题。
    三段按自身归一到 100%，`/rom` 与 `/overlay` 统计口径不一致时也不会把条撑出边界。
  - 图例：色点 → 名称（主色）→ 占比（次要色）→ 容量（主色等宽数字，右对齐成列）；
    可用空间用空心点，一眼区分「已占」和「空着」。
  - 超过 90% 时多一行提示，直接建议清理日志或卸载插件。

## v1.17.0 — 采集跟着页面走、统一 2 秒、修好代理页不刷新

- **概览页砍掉三张卡**：网络端口、网络代理、资源趋势。端口整项数据随之取消采集
  （那是旧版最贵的一段：每个网口都要读 operstate/speed/duplex，还要跑 ip addr），
  模型里的 `PortInfo` 和对应脚本一起删掉。概览现在只剩：实时速度、资源占用、闪存、
  硬件状态、连接设备、系统信息。
- **只在需要的页面采集**（新增 `AppPage` + `PollItem.page`）：
  - 概览页 → CPU/内存/网速/负载/运行时间、温度风扇、闪存、在线设备
  - 网络代理页 → OpenClash 状态与配置、实时流量、连接数与内核状态
  - 设置页 → **完全不采集**，切过去轮询直接停掉
  切页时先立刻取一次这一页的数据，再按间隔继续，不会出现「切过去还是旧数字」。
- **频率统一**：三档秒数合并成一个全局间隔，默认 **2 秒**，范围 1–15 秒，
  设置页只留一个 ± 和几个快捷值。同一页的所有项仍然拼成**一条**命令、一个 shell 跑完，
  所以 2 秒一轮也只创建一次进程。
- **修好「实时流量 / 内核状态不更新」**：旧版指标脚本用的是上一轮状态查询写进
  `openClash.panelPort` 和 `secret` 的值，一旦那条命令失败、或者切页后顺序不对，
  `/traffic` 就会打在默认 9090 上或带着错的密钥返回 4xx，数字永远停在 0。
  现在指标脚本**自己查端口和密钥**，并且三层兜底：带密钥 curl → 不带密钥 curl →
  wget（有些固件只装了 wget）；内核内存/CPU/负载也从 `/proc` 直接取，
  每次刷新都能自己确认运行状态，不再依赖别的项先跑过。
  代理页读不到接口时会明确提示「端口 X 无响应或密码不一致」，不再静默显示 0。
- OpenClash 的模式和配置文件列表要问 7 次 `uci`，改成**只在进入代理页时取一次**，
  之后每轮只确认运行状态、面板端口和流量。

## v1.14.1 — 快档 2 秒、温度/风扇进快档、闪存卡片重做

## v1.14.0 — 大幅降低连接时对路由器的 CPU 占用

现象：App 一打开、连上路由器，路由器 CPU 就冲高，OpenClash 场景下更明显。

定位到的开销（旧版 `poll`，每 2 秒一轮）：

| 位置 | 问题 |
| --- | --- |
| `pollCommand` | 一整段脚本里 **54 次进程创建**；端口那段对每个网口各起 `cat`×3、`ip`、`awk`、`ls\|wc`，网口越多越重 |
| `ocMetricsCommand` | 每 2 秒再起 10 个进程，`uci` 重复读取端口/密钥，`/connections` 每 2 秒让 clash 把整张连接表序列化一遍 |
| OpenClash 状态 | 用 `/etc/init.d/openclash status` 判断，部分固件会 source 整套 shell 函数甚至列防火墙规则 |
| 优先级 | 所有诊断命令都跑在默认优先级，和转发、NAT、clash 抢 CPU |
| 后台 | 退到后台仍继续轮询 |

这一版的做法：

1. **分档轮询**：快档（CPU/内存/网速/负载/WAN 口，3 秒）、慢档（闪存/温度/风扇/租约/端口，12 秒）、
   状态档（OpenClash 开关与配置，20 秒）、指标档（`/traffic` 6 秒、`/connections` 30 秒）。
   一眼能变的指标才值得勤刷，其余全部摊开。
2. **一条命令读完 /proc**：快档改成单个 `awk`，按文件名自动打段标记，不再 5 个 `cat`。
3. **sysfs 用内建 `read` 读**：温度、风扇、operstate/speed/duplex 全部零进程创建；
   端口表先在 awk 里建索引，再用 `set --` 查表，彻底去掉“每口 8 个进程”。
4. **`df` 只跑一次**（`/rom /overlay /` 一次给出三份数据），一块 awk 分发。
5. **`pidof` 代替 `init.d status`** 判断 OpenClash 是否在跑（覆盖 clash / clash_meta / clash_tun / clash_lite / mihomo）。
6. **复用状态查询的结果**：端口和密钥不再每次 `uci get`。
7. **全部脚本 `nice -n 19`**，监控永远不会抢路由工作和 clash 的 CPU。
8. **后台暂停轮询**，回前台自动恢复。
9. 顺手修掉 SSH 读取循环里 `EAGAIN` 的忙等（会占满手机 CPU、拖住路由器 shell），加 30 秒硬超时。

实测（同一台假路由器、4 个网口，统计每轮外部进程创建次数）：

| | 旧版 | 新版 |
| --- | --- | --- |
| 每轮进程数 | 54 + 10 | 快档 2 / 慢档 7 / 指标 2~5 |
| 折算每秒 | ≈ 32 次/秒 | ≈ 1.8 次/秒 |

约 **18 倍**下降，且都在最低优先级上执行。设置里新增「低功耗模式」，可再拉长一档。

（v1.14.1 把快档提到 2 秒、温度风扇并入快档后，折算约 2.2 次/秒，仍只有旧版的约 1/14。）

## 构建

IPA 需要 macOS + Xcode + Apple 签名。当前仓库提供 GitHub Actions 的未签名 IPA 流程。

### GitHub Actions

1. 仓库里要有 `ios/` 和 `.github/workflows/ios-unsigned.yml`，**workflow 文件必须在默认分支上**，
   否则 Actions 页面里根本看不到这个 workflow（或跑的还是旧文件）。
2. Actions → **Build unsigned iOS IPA** → Run workflow，运行器保持默认 **auto**。
3. 下载 artifact `OpenWrtMonitor-unsigned-ipa-macos-15` 或 `...-macos-26`
   （auto 模式下两个池子谁先起来谁先出包，产物内容一样）。
4. 用 Sideloadly / AltStore 配合自己的 Apple ID 签名安装。

#### 一直停在「Waiting for a runner to pick up this job」

那行日志的意思是：任务还没被分配到任何 macOS 机器。**公开仓库的 macOS 分钟免费且不限量**，
所以这跟额度、付款方式都无关，只有两个真实原因：

1. **标签撞上了正在退役的镜像**（最常见）。`macos-14` 将于 **2026-11-02 退役**，
   GitHub 从 10 月起就削减它的容量，还在 10/5–10/31 之间排了 8 个 brownout 窗口
   （每次 14:00–次日 00:00 UTC；其中 10/29、10/30 两段连成 34 小时）。
   这期间用 `macos-14` 的作业会一直排队到超时，或直接失败。
   **先看 Action 页面那行 `Requested labels:`** —— 如果是 `macos-14`，元凶就是它。
2. **两个健康池子恰好都满**。macOS 机器池是共享的，UTC 白天（≈北京时间晚上到凌晨）最挤。

现在这套配置的对策：

| 做法 | 说明 |
| --- | --- |
| 用默认 `auto` | 同时向 `macos-15`、`macos-26` 提交，谁先分到机器谁先跑，两边同时卡住的概率很低 |
| 错峰 | 北京时间上午跑，命中率明显高于深夜 |
| 别连点 | 已加 `concurrency`，同分支新触发会自动取消上一次 |
| 换赛道 | 根目录 `codemagic.yaml` 已备好：Codemagic 免费额度含 macOS M2，起机通常一两分钟 |

标签现状（2026-10）：

| 标签 | 状态 |
| --- | --- |
| `macos-13` | 已于 2025-12 退役，写了永远等不到机器 |
| `macos-14` | **2026-11-02 退役**，容量已被削减，不要再写 |
| `macos-15` | 可用，推荐 |
| `macos-latest` / `macos-26` | 可用，推荐 |

自建 runner 需要一台常开的 Mac（Windows 上装不了 Xcode，租云 Mac 要按月起），
所以没有 Mac 就不存在"零成本自建"这条路。

### Mac 本地

```bash
brew install xcodegen
cd ios
xcodegen generate
open OpenWrtMonitor.xcodeproj
```

或在 `ios/` 下运行：

```bash
chmod +x build-unsigned-ipa.sh
./build-unsigned-ipa.sh
```

生成 `build/OpenWrtMonitor-unsigned.ipa`。
